# MainGameRhythmSync

`MainGameBeatSyncSpeed` と `MainGameSpeedLimitBreak` の実処理を統合したプラグイン。旧名 DLL は互換ブリッジとなり、速度制御の本体はこの DLL に入る。

## 動作

- canon_gate 2.2.0以降を必須とし、H読込完了時にAllPoseRoom判定を共有で1回だけ行う。RhythmSyncと互換Bridgeの3 GUIDを登録し、各GUIDの確定許可に実処理を接続する。
- H中の部屋照会・Hシーン探索・許可再計算・設定再読込みは行わない。マップ変更や例外設定変更は進行中の許可に反映せず、次のH開始から適用する。
- 通常版とVRで同じKKSAPI開始・終了通知を使う。Makerでは、例外許可があってもH用処理を開始しない。
- 許可中は動画再生時刻と曲のBPMを基準にする。音楽の再生時刻・強度サンプリングと、部屋の許可検査は別の処理。
- 低音エネルギーが強い区間は 1 拍、中間は 2 拍、弱い区間は 4 拍でアニメーション 1 周期とする。
- ディルド設定の「リズムシンクに同期」をONにすると、曲の周期・位相を自動往復へ渡す。体位遷移中も曲の時計を継続し、曲停止・同期OFF・H終了では信号を停止する。往復側の速度0は停止を維持する。信号は既存処理から開始・周期変更・シーク・位相補正・停止時だけ通知し、新しい監視ループは追加しない。
- H シーンの参加者を `lstFemale` / `male` / `male1` から取得し、一組の共通速度を全員に適用する。男女別の速度補正は行わない。
- BPM 補正は基準女性の進度から一回だけ計算する。音楽停止・一時停止・同期 OFF・再生情報の失効では全員の補正を解除し、手動速度へ戻す。
- 同じ状態の再生位置差が 0.001 周期を超えた場合は、相手自身の状態を基準女性の位置へ合わせる。時間ゼロの再評価中は AnimationEvent を抑止する。非ループ状態をゼロへ巻き戻さない。
- 体位切替中は共通速度を維持し、切替後に位置を合わせる。シーン終了・人物入替・プラグイン終了時は補正を解除する。
- 拍同期中は速度キューより拍同期を優先する。その他のキュー動作は実行する。
- `LeftAlt+S` で BPM UI を開くと「アニメーションを拍にリセット」ボタンがある。押した瞬間を拍の起点にする。
- 男女同期・Beat解析・Speed変換は各GUIDの許可中だけ有効。未許可の子コンポーネントは無効にし、パッチ・公開APIも処理を始めない。
- H終了・gate停止では許可を失効し、解析結果を破棄、所有ffmpegを停止、速度・音声フラグ・入力を復元する。停止でユーザーの保存設定を書き換えない。
- `pair v=0.2.0` ログに男女全員の ID・状態・速度・再生位置、速度差、位置差を同じ行に記録する。対応状態が異なる場合は `unmatchedStates` を警告として記録する。

## 曲別BPMの音声解析

- 曲別BPM未登録の音源だけ、読み込み・再生開始時に先頭90秒をバックグラウンド解析して保存する。登録済みの曲は自動BPM解析しない。
- プレイバックバーのBPM隣の「BPM解析」は登録済みの曲も再解析する。解析中は重複実行を防ぎ、状態・失敗理由はボタンの説明に表示する。
- 右Ctrlのタップ計測で結果を修正できる。タップ開始・手動保存・曲変更・H終了後に古い解析結果を適用しない。
- WaveTone系の判定中核と既存Python版の独立した音声特徴量をC#へ移植した。WaveTone全体との完全一致を意味しない。無音・短い音源・失敗結果は登録しない。
- 音声の読み出しには同梱またはPATHのffmpegを使う。新しい監視ループは追加せず、メディア通知とメインスレッドへの完了通知を使う。

## 移行

初回起動時、新しいファイルが無い場合だけ旧設定・曲別 BPM マップ・速度キュー JSON をコピーする。旧設定は上書きしない。
旧名の 2 DLL は、BlankMapAdd、カメラ、ライト、サブカメラ、音声効果、HandySync へ旧 API を提供するブリッジとして配布する。

## 制限

アニメーション 1 周期が腰の 1 往復であるモーションを対象にする。別の周期構成のモーションやトランジション中は実機での確認が必要。

## 検証

`dotnet run --project GateTests/GateTests.csproj -c Release` は本物のGateApi・開始停止ソースをリンクし、通常/VR型境界、3 GUIDの許可8組合せ、重複開始、停止復元、Maker拒否、gate停止を検証する。Unity境界はスタブのため、実ゲームの描画・速度・VR操作はユーザー確認が必要。

`dotnet run --project Tests/MainGameRhythmSync.Tests.csproj -c Release` で共通時計の収束、30/60/120fps、60/138/180BPM、1/2/4拍、停止・再開、処理落ちを検証する。
0.2.0 の実機起動・見た目の検証は、ユーザーの起動禁止指示に従い未実施。
