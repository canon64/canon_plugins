# 毎フレーム処理の監査・削減（2026-10-27）

現在の目標は、画質・演出・操作感・垂直同期を保ち、重い場面でも60FPSを維持する処理の余裕を作ること。上限解除や平均FPSだけで完了としない。

## 調査範囲と限界

- 68プロジェクトのソースを機械抽出し、Update・描画コールバック・Harmonyフック・コルーチンから到達する候補を列挙した。
- 抽出結果は `_diagnostics/perf-reduction-20261027/frame-audit.json` に保存し、一度だけ実行する読み込みや変更時処理を毎フレーム負荷と区別した。
- 呼び出し関係の抽出は同名メソッドの候補を含む静的な近似であり、実行頻度やCPU時間の測定結果ではない。
- 画質・撮影間隔・演出・IK・物理の更新頻度は変更せず、60FPS達成の実機判定は未実施。

## 除去した不要処理

| 対象 | 以前の仕事 | 今回の対応 |
|---|---|---|
| 残像と万華鏡 | 撮影ごとに同じキャラ階層を再探索 | 万華鏡のキャッシュを撮影直前に参照し、非表示化と例外時の復元は維持 |
| サブカメラ | 空の対象一覧を毎描画で再探索 | 空結果も保持し、既存の0.5秒間隔で新規キャラだけを検出 |
| サブカメラ | 5秒ごとにRendererキャッシュ全破棄 | 同期・非同期の生成／破棄完了で該当キャラだけ更新し、変化がなければ一覧を再構築しない |
| Renderer更新通知 | 色や表示状態の変更も階層変更扱い | Rendererの構成が変わらない色・表示・親変更を更新通知から除外 |
| ディルドの汗・涙連携 | 連携MOD不在時の全アセンブリ探索とプロパティ探索 | 未使用時は解決せず、型の不在も保持し、追加アセンブリ読み込み時に再解決 |
| 音声予約 | 未来の予約しかなくても毎フレーム空リスト確保 | 期限到達時だけ再利用バッファへ移し、再入・順序・例外時の解放を維持 |
| VMD衣装キー | 13個の設定を毎フレーム反射取得・文字列化 | 設定参照と操作IDを保持し、キー変更イベントで文字列を更新 |
| HandyのBPM連携 | 毎呼び出しの反射引数配列と数値のボックス化 | 一度取得した型付きデリゲートで呼び出し、互換経路は維持 |
| UIヘルプ | 観測用コールバックのクロージャ生成 | 引数を直接渡し、対象外の選択グリッドは先に終了し、例外隔離を維持 |

## 残した処理と理由

| 処理 | 確認結果・維持理由 |
|---|---|
| 位置追従・IK・物理・ゲージの時間積算 | 表示中の位置や動作を毎フレーム追うために必要 |
| 表情・目・音量などの維持 | ゲームや他MODの同フレーム書き込みに追従する必要があり、値の取得まで無条件停止しない |
| ポーズ変更前の全ボーン採取 | PoseInjectorは既に変更直前だけ採取する条件があり、常時の全ボーン採取として扱わない |
| VMDモデルのファイル存在確認 | 変更要求後の遅延再読み込み時だけで、毎フレームのファイルI/Oではない |
| モーション解析・撮影・画像デコード | クリップ変更・撮影要求・画像切替時の処理であり、待機中の通常フレームから区別 |
| シーン・新規キャラ・未生成の外部コントローラー検出 | 未導入MODや遅れて生成されるオブジェクトへの追従用に、既存の間隔付き検出を維持 |
| 追加カメラ描画 | 残像・万華鏡・変位では背景・除外キャラ・撮影時点が異なり、同一画像だと確認できない撮影は統合しない |
| UIヘルプの呼び出し元判定 | マウス行・Repaintに制限済みで、異なる窓の所有者を誤認するキャッシュは追加しない |
| UI入力の取得・解除 | 入力貫通とドラッグの取り残しを防ぐ必要があり、更新頻度を下げない |
