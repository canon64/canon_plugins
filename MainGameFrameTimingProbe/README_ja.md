# 短時間フレーム計測

通常は `Capture.Remaining=0` で停止する。画質・演出・撮影間隔を変更しない。ゲームを起動・操作する機能はない。

`scripts/deploy_timing_probe.ps1 -ArmOnce` はゲーム終了を確認して自身のRelease DLLを配置し、次のHシーンで一度だけ計測する設定にする。Hシーンのアニメーション開始後10秒待ち、メソッド計測なしのフレーム時間を5秒、メソッド計測付きの時間を15秒採取する。終了後に計測フックを外し、Remainingを0へ戻す。フォーカス喪失中は採取を休止し、復帰後に続ける。非フォーカス時間と復帰直後のフレームを集計から除外する。休止中のフックは計測せず、終了または期限切れで解除する。開始後の実時間上限TimeoutSecondsは既定120秒で、期限切れ・採取中のシーン終了は部分結果として終了する。

設定の既定値は `Remaining=0`, `HSceneOnly=true`, `WarmupSeconds=10`, `BaselineSeconds=5`, `DurationSeconds=15`。通常場面を測る場合は `HSceneOnly=false` で一回採取する。通常時・機能未使用時・演出中は別々に採取し、比較中は同じ解像度・キャラ・演出・視点を保つ。設定変更は再起動または既存の設定管理による再読み込みで反映する。

結果は配置先の `captures/*.json` に終了時一括保存する。毎フレームの文字列生成・ファイル出力は行わない。メソッド512件・ネスト64段・フレーム記録8192件が上限。上限超過は結果に記録する。対象はcanon_pluginsから読み込まれたプラグインのUnity更新／描画メソッドと、撮影・変位・液体描画の主要メソッド、コンパイラー生成のIEnumeratorのMoveNext。コルーチン名で絞らず、安価なコルーチン生成メソッドは計測しない。一般の要素列挙用MoveNextは対象外。個々のフック失敗はPatchFailuresに記録する。

HSceneProc.Update／LateUpdateもGAME_INCLUSIVEとして集計する。通常優先度の既存Harmonyフックを含めて囲むため開始はPriority.First、終了はPriority.Lastとする。この時間はゲーム本体や他MODの仕事を含み、canon_pluginsだけの負荷ではない。他のゲーム処理・外部MOD全体を網羅する計測ではない。通常版とVR版の両プロセスを対象にする。

`python scripts/summarize_frame_capture.py <結果.json>` でフレーム時間と負荷上位を表示する。exclusiveは計測対象の入れ子だけを差し引いた時間、inclusiveは子を含む時間。合計の二重計上に注意する。カメラ描画のCPU側経過時間にはドライバー待ちが含まれ得る。Unity側GPU時間を取得できない環境はnullとなり、0msとは扱わない。

前半と後半は連続した別の時間帯であり、最適化の前後比較ではない。計測フック自体にも負荷があるため、後半FPSをそのまま普段のFPSと扱わない。60FPS達成や改善量は、同じ条件での実機確認が別途必要。

`scripts/Invoke-PerfBuild.ps1 -Projects MainGameFrameTimingProbe -TimingProbeRegression` でReleaseビルドと分離テストを実行する。分離テスト57項目では本番集計クラス、固定容量、入れ子時間、JSON保存形式、10万回採取の追加確保0、コルーチンと描画通知とマップ内訳の選択、フォーカス休止／復帰／期限切れ、配置環境のHarmonyによる例外維持・既存フックを含む時間・計測フックだけの解除、Unity内部マーカーの集計と状態復元を確認する。Unity実機の読み込み・描画・FPS確認とは別である。

解除時は成功した計測フックの対象メソッドだけを訪問し、自分の所有IDだけを外す。Harmonyの全体走査によって無関係なVR型の解決に失敗する問題を避ける。次回はマップのUpdate／OnGUIの主要呼び出し先も内訳として測り、全体時間と子の時間を二重加算しない。

60FPS維持の確認用に、16.67ms超過の連続回数、20ms／33.33ms／50ms超過数を集計する。遅い8フレームだけ、その区間の計測対象メソッドのexclusive時間・呼び出し回数を保持する。バッファは開始前に確保し、通常フレームも遅いフレームの入替も追加確保なし。記録と整形は終了時に一括処理する。休止中に途中だった区間の帰属は捨て、復帰後の区間へ混ぜない。

区間は本プローブのUpdate間隔で、Unity全処理を完全に網羅する帰属ではない。垂直同期の待ちを含むため、平均60FPSや16.67ms前後という値だけでCPU/GPUの余裕を断定しない。GPU時間が未取得なら未確認のまま扱う。画質や同期上限を変更して計測値を上げる機能はない。

追加のUnity RecorderはPlayerLoop・スクリプト更新・Camera.Render・スキンメッシュ更新・Physics.Simulate・GC.Collect・描画待ちの8マーカーを両区間で採取する。未対応マーカーやサンプルなしはnullとし、0msとは扱わない。実行中UnityのAPIとマーカー文字列の存在は確認済みだが、この環境で実データを取得できるかは次回の記録で確認する。

オブジェクトごとの描画通知OnWillRenderObjectも有限計測に含め、島の水面反射の追加撮影を計測対象から漏らさない。

Recorderのコストは前半にも含まれるため、前半はメソッドフックなしの区間として読む。既存のスレッドフィルターは変更せず、他の利用者が有効にしていたRecorderも無効化しない。自分で有効にしたRecorderはフォーカス休止中に停止し、復帰で再開、終了で元に戻す。複数スレッドと重複範囲を含み得る各マーカーを単純合算してフレーム時間とはしない。フレームごとの確保やログ出力は追加していない。
